    Self-service access on the developer portal

    Turned a manual access-request process into a form on our Backstage developer portal: submit it, and a GitHub issue is filed through the API and the right team leads get pinged in Slack.

  2. 02
    • TypeScript
    • Vitest
    • Slack API
    • GitHub Actions

    Developer announcements, rebuilt in TypeScript

    Replaced a pair of Bash scripts with a tested TypeScript service that publishes weekly developer announcements to Slack — and can edit ones it already sent.

    How it works

    Announcements queue up as issues and ship on a schedule, with an urgent path that publishes immediately. The rewrite made the pipeline unit-testable, then unlocked three things the Bash version couldn't do:

    • Editable messages — the Slack message ID is persisted back to the issue, so an edit updates the original post instead of stacking corrections in a thread.
    • Author attribution — GitHub users mapped to Slack IDs, so readers know who to ask.
    • Tag-driven color coding — a tag on the issue sets the message's accent color by category.
  3. 03
    • TypeScript
    • LLM prompting
    • Slack API
    • GitHub Actions

    AI pipeline for developer pain points

    Built a daily-to-monthly pipeline that reads our developer support channel and tells platform leads which parts of the platform actually hurt — classified by area, counted weekly, summarized monthly.

    How it works

    A daily action pulls the last 24 hours of support messages and filters the noise — bot posts, join events, and one-word replies that carry no signal.

    A weekly action classifies what's left. Each message goes through a regex keyword pass built from vocabulary I collected from the leads of each platform area, then to an LLM with that context attached and prompting tuned to return exactly one category token. Counts per area go to Slack every week.

    A monthly action pools a month of classified messages by area and asks for ranked pain points with suggested remediations, grounded only in the messages themselves — no outside speculation. That summary goes to managers and team leads.

    Before any of it, I ran a spike comparing three storage backends — vector search, expiring CI artifacts, and a durable artifact repository — and wrote up the tradeoffs. Vector search can't reliably answer "everything from last week," and expiring artifacts make past classifications impossible to audit, so durable storage won.

  4. 04
    • Kubernetes SDK
    • Helm
    • TypeScript
    • GitHub Actions

    Kubernetes namespace provisioning

    Designed and built the system that provisions custom Kubernetes namespaces on demand. Teams used to get exactly one namespace per cluster, tied to the team name — a second one meant inventing a second team.

    How it works

    Namespace definitions live in config as code. The action reads the changed files on a pull request, works out which clusters are affected, and provisions through the Kubernetes SDK and Helm APIs — namespace, permissions, and the tenant chart that makes it usable.

    • Ported a large Bash provisioning action to TypeScript first, so the new work had a testable foundation.
    • Scoped each namespace to specific repositories rather than every team with cluster access — a much smaller blast radius for deploys.
    • Added retry and rollback around Helm upgrades, which is where provisioning most often got stuck.
    • Ran end-to-end tests until custom namespaces had full parity with the original team namespaces.
